# Database Design

## Database Choice

The Smart Health Surveillance & Early Warning System will use a relational database to ensure data consistency, integrity, and efficient querying.

A relational database is well suited because the application contains multiple interconnected entities such as users, patients, disease reports, laboratory reports, notifications, and alerts. These relationships require strong consistency and structured data management.

The final database technology will be selected during the implementation phase.

---

## Tables

The following entities have been identified for the initial version of the system.

| Entity            | Description                                                   |
| ----------------- | ------------------------------------------------------------- |
| User              | Stores information about all authenticated users.             |
| Role              | Defines user roles and permissions.                           |
| Health Center     | Stores hospitals, PHCs, clinics, and other health facilities. |
| Patient           | Stores patient demographic and health information.            |
| Disease           | Stores master information about diseases.                     |
| Disease Report    | Stores suspected and confirmed disease cases.                 |
| Laboratory Report | Stores laboratory test results.                               |
| Notification      | Stores notifications sent to users.                           |
| Alert             | Stores outbreak alerts generated by the system.               |
| Audit Log         | Stores important user activities for security and auditing.   |

Additional entities may be introduced as the project evolves.

---

## Relationships

The major relationships between entities are:

* One Role can be assigned to many Users.
* One Health Center can have many Users.
* One Health Center can register many Patients.
* One Patient can have multiple Disease Reports.
* One Disease can appear in multiple Disease Reports.
* One Disease Report may have one or more Laboratory Reports.
* One User can receive many Notifications.
* One User can generate many Audit Log entries.
* One Alert may be associated with multiple Disease Reports.

These relationships will be refined during the database modeling phase.

## Indexing Strategy

The indexing strategy will focus on improving search performance for frequently accessed data.

Potential indexing areas include:

* User email and username.
* Patient identification number.
* Disease name.
* Disease report date.
* Health center.
* Geographic location.
* Alert status.

The final indexing plan will be implemented after analyzing application queries and performance requirements.
